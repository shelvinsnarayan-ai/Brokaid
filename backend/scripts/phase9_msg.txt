Scope
-----
- plAIce agent (app/kernel/agents/placement.py) — EmergentLLMProvider-
  Placement. Own system prompt, own tool `record_placement_draft`
  with tool_choice='required'. Class allow-list:
    submit_to_market, endorsement_execute_instructed_quoted,
    endorsement_standard, renewal_pack_unchanged.
  Other classes → AgentClassMismatch → brAIn emits
  AgentInvocationCompleted{outcome:'error'}.
  Refusal path: shaped empty output with class_key='_invalid_class_'
  and refusal reason in provider_meta.notes.
- Prompt (app/kernel/agents/prompts/placement.md) — fresh, plain
  broker-placement voice; six hard rules (never state a premium,
  never state coverage position, never speak for the insurer,
  always cite underwriter answers, new-cover-mid-term → binder
  reroute, tool-only output); one worked example inline.
- Registry (app/kernel/providers/registry.py) — 'placement' now
  resolves to a fresh EmergentLLMProviderPlacement per invocation.
- MOCKED CarrierChannel (app/kernel/mocks/carrier_channel.py) —
  deterministic per envelope_id (RNG seeded from SHA-256 of the
  envelope), FICTIONAL PRICING (5% of PL limit delta; 6% products;
  4% PI; 10% flat for new cyber; $120/head for headcount).
  Every response carries mocked=true; ledger event mirrors flag.
- Orchestration (app/routes/o_placement.py) — POST /api/o/matters/
  :matter_id/place. AE or Principal only. Loads intake output,
  builds placement envelope, invokes brAIn on 'placement', calls
  submit_endorsement, emits three synthesis events on success:
    SubmissionDrafted (plAIce's real output, mocked=false)
    CarrierQuoted (mocked=true, MOCKED · CARRIER pill)
    EndorsementQuoteReady (synthesis, watched by client surface)
  On class_reroute → emits PlacementRerouted, no carrier call.
- Client pending-quote surface (app/routes/c_pending_quote.py) —
  GET /api/c/policies/:policy_id/pending-quote. Returns the latest
  EndorsementQuoteReady for the policy that has no downstream
  EndorsementExecuted, joined to its SubmissionDrafted and
  CarrierQuoted. Response body scrubbed of model_id + provider_meta.
- /c/cover/:policy_id/pending page — new client route rendering the
  quote card. Harbour surface, MockedBadge label='carrier' prominent,
  premium-change in DM Mono, plain-English submission summary, two
  scaffolded buttons (Approve+pay and Ask a question).
- Decision Card lineage (queue.py) — /api/o/queue/:envelope_id now
  appends SubmissionDrafted + CarrierQuoted + PlacementRerouted +
  EndorsementQuoteReady events (keyed by envelope_id) to the
  evidence list. Operator surface reads them inline.
- KEvidence.tsx — CarrierQuoted evidence rows now show a
  "mocked · carrier" chip and inline carrier line
  (carrier_name · new annual · change · terms).
- pending-quote.css — new Harbour card treatment.

Deviations
----------
- Same pinned model as intAIke. Rationale: same call site posture
  (structured tool-use, no streaming, server-to-server), no per-
  agent latency budget yet. If a lighter model beats it in
  hardening (phase 16), we swap and update PINNED_MODEL_IDS in one
  place.
- The operator-facing POST /api/o/matters/:matter_id/place is
  exercised by tests and a Python demo script; a UI button lives
  in the phase-11 endorsement scene. Phase-9 scope was to prove
  the orchestration + evidence surface.
- Placement route uses only 'principal' and 'ae' active_role
  values. If your session role map uses 'account_executive' full,
  add it to the guard; brief listed AE, current dev users only
  seed 'principal'. Not blocking — the seeded principal is
  authorised.
- No CarrierExecuted / EndorsementExecuted event emitted in this
  phase. That's phase 11's job. The client's "already_executed"
  branch on GET /pending-quote is there for that future path.
